Dependency-free C implementation of a UDS (ISO 14229) server and client with built-in ISO-TP, for building embedded ECU targets and test tools.

## What it is

A UDS server *and* client library for embedded systems, in C, by
driftregion. MIT-licensed. It ships as two files — `iso14229.c` /
`iso14229.h` — with examples for ESP32, Arduino, NXP S32K144, STM32,
and Zephyr; its README cites use by Mercedes-Benz ARDEP and B&R
Automation Runtime.

## How it works

Static memory allocation only (no `malloc`). ISO-TP (ISO 15765-2)
transports are included — the embedded isotp-c, Linux ISO-TP sockets,
or bring-your-own. The documented service matrix shows both server and
client implementations for most core services (0x10, 0x11, 0x22, 0x27,
0x28, 0x2E, 0x31, 0x34–0x38, 0x3E, 0x85), including a
`linux_security_access` example implementing 0x27 with a cryptographic
challenge-response; 0x19, 0x23, 0x24, 0x2A, 0x2C, 0x84, and 0x86 are
unsupported on both sides, and a few services (0x14, 0x2F, 0x3D, 0x87)
are server-only.

## Where it fits

Putting a UDS server (ECU- or bootloader-side) or a small client onto a
microcontroller in C — the embedded counterpart to
[udsoncan](udsoncan.md)'s Python client, and the natural pairing for
the simulator work in [UDSim](udsim.md) and
[uds-server](uds-server.md).

## Limits and notes

The README states the API status verbatim: "Major version zero (0.y.z)
(not yet stable). Anything MAY change at any time." Service gaps per
the matrix above. No vehicle-safety warning is stated in the checked
sources.
